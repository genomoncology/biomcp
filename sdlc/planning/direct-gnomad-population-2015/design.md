October 7, 2026. Owning global BioMCP ticket [2015](../../tickets/2015-adopt-direct-gnomad-population.md), milestone 1.0, component backend. DESIGN only. Root assigns fresh review before producer allocation and BUILD. This draft starts at consumer d6aa002f and BioData main b0fc4ec3; Cargo pins dbbaa1ae, version 0.0.37.

## Selected boundary and actual callers

GnomadClient::variant_population reads a bounded HTTP response into GraphQlResponse<VariantPopulationResponse>. The local variant graph stores exome/genome sequencing records, ancestry rows and FAF95. parse_variant_population_response interprets GraphQL errors and then mutates all overall and ancestry allele_frequency fields using ac/an. get.rs::add_population checks the returned variant ID, selects section outcomes and creates GnomadPopulationResult. That product result contains local sequencing records. markdown/variant.rs separately serializes population for its template and reads rows for highest-frequency selection and filter explanations.

These callers support a complete direct-population graph migration. A whole Variant migration would also have to settle unrelated live-provider models and product policy. The selected graph removes four actual local value owners and its source mapping without leaving a copied nested response model. Shared graph adoption does not establish whole variant entity completion. Search continues to use the already adopted cached MyVariant AF values.

BioData owns source facts and the count ratio. BioMCP owns HTTP, caching, retries, GraphQL error interpretation, returned-ID correlation, GRCh38/dbSNP admission, section requests and outcomes, dataset/release/caveat strings, provenance, highest-row display selection, ancestry labels and filter explanations. Keep gene_constraint and its GraphQL response types unchanged. GraphQlResponse and VariantPopulationResponse remain product envelope owners; their optional variant member delegates to the shared decoder. Do not add a general GraphQL library or transplant product envelope policy.

## Finite proposed library API

Add a cohesive adapters::gnomad_v4 module. Export GnomadV4Population, GnomadVariantPopulationProjection, GnomadSequencingPopulationProjection, GnomadFaf95Projection and GnomadAncestryPopulationProjection. All records have private fields, Clone and safe Debug that prints type names only. Decoder construction validates the admitted finite numeric forms; there are no public setters, generic dynamic carrier, HTTP dependencies or clinical validity rules.

GnomadV4Population::deserialize_variant<'de, D: serde::Deserializer<'de>>(D) -> Result<GnomadVariantPopulationProjection, D::Error> consumes the existing source variant member. The local envelope's optional bridge handles missing/null before calling it. It consumes the original streaming source representation; no source Value, serialization/reparse or whole-hit conversion is introduced. A local Deserialize wrapper lets the existing decode_json_response HTTP/content-type validator call it without changing the generic source decoder.

Variant getters are variant_id() -> &str and exome()/genome() -> Option<&GnomadSequencingPopulationProjection>. Sequencing getters are allele_frequency() -> Option<f64>, ac()/an()/homozygote_count()/hemizygote_count() -> u64, filters() -> &[String], faf95() -> Option<&GnomadFaf95Projection>, populations() -> &[GnomadAncestryPopulationProjection]. FAF getters are popmax() -> Option<f64> and popmax_population() -> Option<&str>. Ancestry getters are id() -> &str, allele_frequency() -> Option<f64> and the four count getters. An into_parts(self) -> (Option<GnomadSequencingPopulationProjection>, Option<GnomadSequencingPopulationProjection>) method transfers the two authoritative records to the product envelope without constructing another graph.

Each sequencing record exposes as_population_target() -> a named borrowed encoder and deserialize_population_target(D) -> Result<Self, D::Error>. The encoder delegates its nested FAF/ancestry fields and emits the existing eight sequencing keys in order: allele_frequency, ac, an, homozygote_count, hemizygote_count, filters, faf95, populations. Each ancestry record also exposes as_population_target() -> GnomadAncestryPopulationTarget, a named borrowed encoder for the selected ancestry rows passed directly into MiniJinja. It uses the same field encoder as nested sequencing output. Ancestry emits id, allele_frequency, ac, an, homozygote_count, hemizygote_count. FAF emits popmax, popmax_population. Optional members emit explicit nulls as the current source structs do. Export the named sequencing encoding type if required by its public return signature. No model derives convenient Serialize/Deserialize, stable document or catalog entry is added.

The product stores Option<shared sequencing record> in GnomadPopulationResult.exome/genome. An optional Serde bridge uses the shared target encoder/decoder. The separate Markdown template input serializes this product envelope through those bridges. Direct renderer getters borrow the same records. The selected exome/genome ancestry rows pass their borrowed ancestry encoders into MiniJinja; selection remains BioMCP policy. There is no temporary product mirror and no field-by-field target reconstruction.

## Source and product-target admission

Preserve the current source shape. variant_id is a required string without new coordinate or vocabulary validation. exome/genome are independently missing/null or complete records. Each sequencing record requires unsigned integer ac/an/homozygote_count/hemizygote_count, string-array filters and ancestry-array populations. Each ancestry row requires its string id and the same four unsigned counts. faf95 may be missing/null; present FAF allows independently missing/null finite popmax and string popmax_population. Empty strings, arbitrary raw flags/IDs, duplicate ancestry rows and their order remain admitted. Do not enforce ac <= an, count relationships, frequency range, ancestry vocabulary or nonempty IDs.

Source allele_frequency accepts the current optional finite numeric/null form but never overrides counts. Compute every overall and ancestry frequency as None for an == 0, otherwise Some(ac as f64 / an as f64), including zero ac and ac > an. Keep the same cast/division order. An admitted source frequency is recomputed once. Missing required counts/lists, null required lists, negative/fractional/overflow counts and wrong known field types fail. Preserve serde's current rejection of duplicate known fields and tolerance of unknown fields, including consuming ignored nested values.

Product-target decoding is a distinct direction. Current Variant Deserialize accepts independently supplied allele_frequency values in display fixtures and other in-process callers. The target decoder retains those supplied finite values or null/missing; it does not recompute them from counts. This distinction preserves the existing response/renderer contract while the source decoder remains count-derived. JSON cannot contain NaN/infinity; the shared value does not admit them. Retain the renderer's defensive nonfinite-frequency selection claim at its numeric selection boundary without inventing nonfinite shared source records or duplicating a mutable row type.

The original 512 KiB source body limit and serde recursion admission remain product-owned and unchanged. The embedded decoder fully consumes ignored fields/tails under those limits. It adds no lower list/text/resource ceiling. Errors from the library expose static sanitized structure diagnostics and no provider text or input in Debug/Display/source chains. The existing product section maps failed parsing to unavailable using its static message. GraphQL message handling remains local, including: not-found only when no variant and at least one nonblank message exists and every such message equals Variant not found ignoring case; errors alongside usable data remain failures; nonempty errors without messages remain GraphQL request failed. No section privacy relaxation is authorized.
