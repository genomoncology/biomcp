# Execute the BioData NCI trial detail plan

## Outcome

Every live NCI trial detail request uses BioData `0.0.5` to define the credential-free request, validate the one-row response envelope against the requested NCT identity, and project the shared trial values. BioMCP keeps the API key, HTTP execution, cache, retry, product conversion, section selection, and rendering. NCI search remains unchanged.

## Current facts

At BioMCP `e3f108d01096838b96f6e89e7cfe4dc93c25480a`, `NciCtsClient::get_plan` requests a bare `trials/{nct_id}` record with an `X-API-KEY` header. `NciCtsClient::get` decodes that record into `serde_json::Value`. `transform::trial::from_nci_trial` and `entities::trial::get::nci_eligibility_text` parse the same detail record again. Search uses a separate JSON path and must remain unchanged.

BioData `9c470d5d3aad97b34bd4be71924475c03973a331` exports version `0.0.5`. `NciCtsV2DetailPlan` validates and normalizes an NCT identity and returns the `trials` path plus ordered query pairs. Those pairs contain `size=1`, `nct_id=<normalized identity>`, and sixteen repeated `include` keys. The fields are `nci_id`, `nct_id`, `brief_title`, `official_title`, `current_trial_status`, `why_study_stopped`, `study_protocol_type`, `phase`, `diseases`, `minimum_target_accrual_number`, `arms`, `lead_org`, `start_date`, `completion_date`, `eligibility`, and `brief_summary` in that order. `NciCtsV2DetailResponse` accepts only the successful envelope bytes bound to the plan. It rejects missing, multiple, or mismatched rows. Its projection owns the shared trial values and conversion report. Its temporary accessors expose the source summary, structured eligibility, and source sex spelling until those values finish migration.

The existing receipted NCI payload proves the provider record shape and product conversion. Its request did not use the new allowlist and included contact-bearing fields. It cannot prove the exact live request. Local loopback tests must construct an allowed response from recorded evidence. A human-run credentialed smoke test remains required before claiming that the exact field-selected request works against the live provider.

## Scope and decisions

Keep the exact BioData `0.0.5` dependency and lockfile revision already landed by record 1170. Keep BioMCP as the only owner of `NCI_API_KEY`. Translate every BioData query pair into the existing request abstraction without combining repeated `include` keys. Add exactly one `X-API-KEY` header. Keep the current no-store cache behavior, retries, timeout, bounded response reader, base-URL override, and source-aware errors.

Build the plan only after BioMCP validates the NCT input. A BioData plan error after that validation is an internal processing error. Send `GET /api/v2/trials` with the exact ordered query. The query and diagnostics must not contain the credential. The query must not request sites, contacts, principal investigators, email, phone, or primary purpose.

Inspect HTTP status before BioData parses the body. Improve HTTP 404 handling with `BioMcpError::NotFound { entity: "trial", id: <normalized requested NCT identity>, suggestion: "Try searching: biomcp search trial -c \"<normalized requested NCT identity>\"" }`. The current NCI detail path reports 404 as a generic API failure. Map every other non-success status to a fixed NCI API error that contains the HTTP status only and carries retry recovery. Do not use the current generic JSON decoder for these status errors because it stores a provider-body excerpt. This rule applies when a non-success body contains valid JSON. Read the successful body once and pass the same `Vec<u8>` directly to `NciCtsV2DetailResponse::parse`. Do not deserialize and reserialize the detail response before BioData receives it.

Map BioData `not_found` to the same product not-found result. Map `json_resource_limit` to a sanitized NCI API error with narrow-request recovery. Map `malformed_json`, `unsupported_json`, `invalid_projection`, `unexpected_row_count`, and `identity_mismatch` to sanitized NCI API errors with retry recovery. Include only the stable BioData error code in these API messages. The normalized requested identity may appear only in the not-found value and suggestion. No API error may store provider bytes, provider values, a returned identity, the requested identity, or the API key. Tests must inspect public output, `Display`, and `Debug` representations.

Convert the product trial from the plan-bound BioData projection. Use the plan-normalized identity. Preserve the current useful NCI output for admitted provider records: brief title, current status, phase, study type, conditions, intervention names, sponsor, enrollment, dates, stopped reason, summary, age range, structured age and sex eligibility, and rendered eligibility text. Keep the `NCI CTS` source label. Keep the current twenty-five-intervention display cap until the arms area reviews it. Normalize the summary exactly as the current product does. Convert shared `u64` enrollment to product `i32` with a checked conversion. Leave an out-of-range enrollment absent.

Preserve the age behavior proved by the admitted provider record. Keep the source maximum spelling in the typed age range. Continue rendering the provider's `999 Years` sentinel as `Any age` in product text without adding a new clinical interpretation to BioData. Accept BioData's stricter boundary for malformed and incomplete detail records. BioMCP currently turns some missing required fields into empty product values, treats malformed structured eligibility as absent, retains unsupported age text such as `18 Years old`, and accepts string-valued enrollment. The new path must reject those values as sanitized source failures under BioData's stable error code. This intentional change prevents malformed provider records from appearing as successful trials.

Build eligibility text from the ordered shared criteria. Preserve the inclusion and exclusion headings, stable source order, and current twelve-thousand-character truncation. Do not parse eligibility from raw JSON in BioMCP. The plan must request eligibility for every NCI detail call because overview output still carries the age range. Return structured eligibility and eligibility text only when the caller requested `eligibility` or `all`. Keep the top-level age range in overview output.

Preserve the product's explicit stopped-reason shape with `Some(projection.stop_reason().map(str::to_owned))` because the plan always requests that field. Return an empty reference list when references were requested. NCI does not provide references in this plan. Leave contacts, locations, outcomes, product arms, intervention details, and eligibility provenance absent during this adoption. The later areas own those additions.

Remove the obsolete NCI detail parser after the new path works. Delete or replace `transform::trial::from_nci_trial` and the raw-JSON `nci_eligibility_text`. Move their useful behavior tests to the plan-bound conversion. Keep `transform::trial::from_nci_hit` and all NCI search behavior. Retain the NCI fixture attestor and every on-disk receipt entry. Retain the `from_nci_hit` search boundary unchanged. Remove only the `from_nci_trial` and `nci_eligibility_text` detail-function boundaries and their mutation tests from the capture-receipt manifest checks. Do not invent a new BioMCP raw-JSON detail boundary because BioData owns those keys. Keep the manifest checker active.

Use existing Rust test modules and the existing loopback process test surface. Do not add a packaged file. The package must remain at or below 1,300 files. Keep private-content, package-root, and source-provenance checks active.

Do not change NCI search, ClinicalTrials.gov behavior, public command schemas, output formats, provider scope, release versions, or unrelated BioMCP behavior. Do not perform a live credentialed call in unattended work.

## Review

- Design review: rejected because the first draft promised blanket behavior preservation across malformed records, referred to NCI not-found behavior that did not exist, allowed status errors to retain provider excerpts, and left the receipt-manifest update ambiguous. The corrected design preserves admitted provider behavior, adopts stricter validation explicitly, defines the new not-found value, forbids stored excerpts, and names the exact provenance-boundary changes. Independent re-review accepted the corrected contracts as explicit, internally consistent, and testable.
- Code review: the first implementation review rejected three gaps. The ignored live smoke selected `nci_id` even though the BioData plan requires an NCT identity. The plan-bound eligibility tests did not directly prove stable criterion ordering and heading transitions, exact post-composition truncation, missing criteria versus explicit empty criteria, or the `all` path. The remediation adds a request marker only for NCI detail, lets that marked path classify a non-success status before any body read, uses `nct_id` in the live smoke, and adds each missing plan-bound assertion. Every other source retains the prior response-limit behavior. Independent re-review accepted all three corrections and found no remaining correctness, privacy, ownership, search, provenance, package, or test gap.
