# Render BioData arm assignments for both trial sources

## Outcome

The real BioMCP trial detail command renders interventions, arms, and arm-to-intervention assignments from the latest BioData development version for ClinicalTrials.gov and NCI. BioMCP stores the shared BioData entities once, serializes their source-supported fields directly, and groups Markdown arm rows through typed identities. Every ClinicalTrials.gov detail path that requests arms and the NCI `arms` and `all` paths consume untouched provider bytes through BioData.

## Current facts

At BioMCP `714fb38fd7e6b046b7f3d7d38894aa86692fa855`, the application pins BioData `0.0.5` at `9c470d5d3aad97b34bd4be71924475c03973a331`. ClinicalTrials.gov detail parsing still stores intervention data in a string list, `TrialIntervention` objects, and `TrialArm` objects whose relationships are intervention-name strings. `transform::trial::extract_arms` chooses the arm-side names when present and otherwise joins intervention arm labels to arm labels. NCI detail already sends untouched bytes through BioData, but product conversion caps intervention names at twenty-five, discards intervention detail, and leaves arms absent.

BioData `0.0.6` at `375994eda1cb1f285141fc4797d758a7ebfa8806` supplies portable trial-local arm and intervention identities, typed assignments, types, descriptions, aliases, strict relationship validation, and source-specific projections. Its ClinicalTrials.gov plan can request the dedicated arms area with eighteen base fields plus five arm relationship fields. Its NCI complete projection contains every nested occurrence. The admitted NCI response contains two arms, fifty-three intervention occurrences, and fifty-three assignments. Duplicate names remain distinct occurrences.

The BioMCP capability contract permits improved JSON and Markdown when useful information and operations remain available. Exact historical bytes are not a goal. `Trial` currently derives both serialization and deserialization, the generic JSON renderer serializes it directly, location pagination flattens a borrowed trial, and one surface contract deserializes it. The shared BioData types do not implement Serde traits because BioData keeps domain values separate from stable wire contracts.

BioData `0.0.7` at `65f6af05720fdc0fbf630578be98ea34d77122d6` adds opt-in ClinicalTrials.gov request builders for eligibility, contacts, locations, outcomes, and posted documents. BioMCP can compose one outbound plan for dedicated, mixed, and `all` requests. Product section policy remains in BioMCP: `all` includes arms, references, eligibility, contacts, locations, and outcomes but excludes documents; eligibility also adds documents for provenance; an explicit documents request adds documents; mixed requests union only their selected groups.

## Scope and decisions

Update the Cargo Git dependency, lockfile, and package-development contract to BioData `0.0.7` at `65f6af05720fdc0fbf630578be98ea34d77122d6`. Do not publish BioData or BioMCP.

Replace `Trial::interventions`, `Trial::intervention_details`, the product-owned `TrialIntervention`, product-owned `TrialArm`, and embedded arm intervention names with one flattened `TrialDesign` value. `TrialDesign` owns one ordered `Vec<biodata::ClinicalTrialIntervention>`, optional ordered shared `ClinicalTrialArm` values, and optional ordered shared `ClinicalTrialArmInterventionAssignment` values. Its constructor and deserializer validate the complete relationship through BioData's public relationship value. The product trial owns each shared collection once after a provider response is consumed.

Keep `Trial` serialization and deserialization supported. Give `TrialDesign` a local Serde wire adapter that encodes the three public JSON members through BioData getters and reconstructs every shared value through BioData constructors. The wire adapter is a transient boundary value. It is not stored after conversion. It rejects invalid IDs, duplicate IDs, duplicate assignment pairs, and dangling endpoints. Flatten it into `Trial` so unrelated JSON members and generic serialization paths remain unchanged. Borrowed Markdown views read the same stored values.

Change structured JSON deliberately. `interventions` becomes an array of objects with `id`, `name`, `type`, `description`, and `other_names`. `arms` becomes an array of objects with `id`, `name`, `type`, and `description`. Add `arm_intervention_assignments` with `arm_id` and `intervention_id`. Remove `intervention_details`. Update the public trial schema, examples, specifications, snapshots, and tests. Do not retain parallel compatibility fields.

Represent each arm and intervention `type` as either JSON null or one complete BioData extensible-code object. The object has exactly `authority`, `code`, `display`, `vocabulary_version`, and `recognized_meaning`. `authority` and `code` are required nonempty strings. The other three members are required nullable strings and preserve nonempty source-supported values without inference or normalization. Reject missing members, unknown members, empty required strings, and empty present optional strings. Preserve unknown future codes when the object is otherwise valid. ClinicalTrials.gov and NCI retain their distinct source authorities. Serialization always emits all five object members in that order so one encoded `Trial` can reconstruct the same shared values without consulting `Trial::source`.

Keep overview Markdown bounded to the first five interventions and report the correct remaining count from the complete shared collection. Display at most five assigned intervention names per arm and print an exact omitted count in that arm cell. Keep the existing 60-character arm-description presentation. Resolve an arm's displayed interventions by typed assignment identities and intervention identities. Never compare names or labels. Preserve deterministic source order.

Preserve related-command selection exactly. The completed-trial article search uses the first intervention in source order by name. The ordinary related block scans interventions in source order and chooses the first nonblank alias from the first intervention that has one, then emits the current alias-based drug search. When no intervention has an alias, it uses the first intervention name and emits the current drug search and drug-trials commands. Keep existing quoting, safety, and command deduplication. Mutation tests pin which occurrence wins.

Build every ClinicalTrials.gov detail request from `ClinicalTrialsGovApiV2DetailPlan`. Compose the reviewed builders from normalized product section selection. The base overview request uses the base plan. Arms, references, eligibility, contacts, locations, outcomes, and documents add their BioData builders under the exact product composition rules above. Execute one request through the existing base URL, cache, retry, timeout, response limit, status, and safe-error policies. Pass the same successful bytes directly to BioData before or beside temporary legacy decoding. Do not deserialize and reserialize before BioData receives them.

Populate product interventions, arms, and assignments only from BioData for every ClinicalTrials.gov detail path. Missing or null requested arm data yields an absent product arm section. Explicit empty arms yield present empty arms and assignments. Populated values preserve identities, descriptions, aliases, and assignment order. Map BioData failures through the same sanitized stable-code policy as the accepted reference path. Unknown or ambiguous source labels must surface as `invalid_projection` without source values in output, stored messages, `Display`, or `Debug`.

Temporary legacy decoding may continue for unmigrated ClinicalTrials.gov values from the same response bytes. Clear or bypass the legacy arms and interventions module before product conversion. Delete `transform::trial::extract_arms` and all legacy intervention extraction for detail responses. Keep search, eligibility, contacts, locations, outcomes, documents, and unrelated legacy conversion unchanged.

For NCI detail, build the product intervention collection from every shared intervention in the existing plan-bound complete projection. Remove the twenty-five-item data cap. Keep Markdown presentation bounded. When `arms` or `all` is requested, populate shared arms and assignments from that projection. For overview and unrelated sections, omit arms and assignments while retaining complete interventions. Preserve duplicate intervention occurrences and identities. Keep credentials, HTTP, status-before-body-limit behavior, cache, retry, summary, age, eligibility, source label, and NCI search unchanged.

Keep the private reference wrapper unchanged in this ticket. Record its removal as the immediately following BioMCP ticket and complete that cleanup before eligibility begins. This split keeps reference nullability and absent-versus-empty behavior independent from the arm migration while honoring ADR 0029's removal trigger.

Add one real-process loopback contract per source or one parameterized contract that invokes the actual CLI and raw and typed MCP paths against local provider servers. The servers assert the exact provider request where the path is exact. Tests pass original recorded or admitted synthetic response bytes into BioData. They verify JSON structure, Markdown grouping, section selection, source order, duplicate NCI occurrences, safe failures, and equal raw and typed MCP relationship data. Synthetic inputs may prove ambiguity and mutation behavior. They do not replace recorded provider support evidence.

Keep net production Rust growth at or below 250 lines after deleted product values, extraction, and render logic are counted. This reserves at least half of the checkpoint's 500-line allowance for eligibility. Do not add a generic migration framework, second provider call, new capture, live credentialed call, source search change, release version, reference cleanup, or unrelated cleanup. Keep the package at or below 1,300 files and keep every current public and provenance policy active.
