# Parallel article cache qualification

The parallel article cache test treated every successful provider request as an admitted cache response. Its second search-all command still fans out internally, so running it after the first process exits does not guarantee uncontended admission. The corrected proof reads admitted HTTP response identities from SQLite and requires every admitted Europe PMC and MyGene answer to be reused.

## Original failure and diagnosis

Work starts from published brief revision `7082c89de`, based on main `4c582db4186837893e4839f6d47e5e60a129aae7`. The branch fast-forwarded to its own published progress revision `347170814d9f26fbf9f889425ba177c58fe4d8fb` before implementation.

Final Linux job `2233/1792455276832-365318` failed only `test_parallel_article_sources_fill_cold_cache_then_reuse_answers[command1]` at the strict warm-reuse assertion. Its nominal admission and final search-all commands returned the same payload as the cold command. The final command repeated the Europe PMC `GENE_PROTEIN:BRAF AND melanoma` search with `pageSize=25`. The original cache directory had already been deleted by replay borrow teardown, so the evidence cannot establish whether that response had been admitted. This correction does not claim to recover the original runtime cause or a successfully acknowledged write that disappeared. The run passed 4,279 routine Rust cases and 1,587 Python cases, with one Python failure and five Python skips.

M5 diagnosis job `2285/1792457442616-5675` ran the original test with only the cache-retention correction. Its uncontrolled command1 case passed with twenty stored entries after each phase and no repeated cacheable keys. An existing `BEGIN IMMEDIATE` control held across cold and nominal admission commands produced correct, identical returned payloads and zero stored entries. Debug logs explicitly reported skipped cold writes and skipped admission initialization. After release, the final call stored twenty entries and repeated both Europe PMC and MyGene requests. The original test first rejected debug cache diagnostics; an independent evaluation of its unchanged strict request predicate also rejected those permitted refetches. This controlled result demonstrates the contract mismatch and does not reproduce the unknown original Linux cause.

## Correction

The fixture moves its existing run directory under pytest's owned case directory and passes its cache through the existing `retained_cache_env(cache_dir=...)` control. A retained pytest base directory now preserves the command home, config, datasets and SQLite database together after replay teardown. No shared fixture helper changed.

The cold command, nominal admission command, final command and their exact full result or section equality assertions remain. The final warn-level cache diagnostic assertion remains. Before the final call, the test snapshots HTTP response URLs from SQLite and derives their exact replay keys. The existing article query translation is defined once locally and shared with the provider handler. Canonical query ordering preserves the replay server's identity rules. Every admitted key must correspond to a successful earlier fixture request, and no final request may repeat an admitted key.

For search-all, one standalone gene search provides a bounded uncontended admission before the snapshot. It returns the exact gene section payload. Both commands use the same MyGene request identity with `size=50`; the test requires exactly one such earlier identity and requires it in SQLite. The standalone invocation owns its cache and performs one provider request without competing provider writes. EuropeOnly article search already awaits its primary Europe PMC response and cache write before enrichment. Its exact primary `pageSize=25` request must be admitted. These checks give each parameter a real admitted answer without requiring every best-effort write to succeed or adding a retry loop.

A single sweep covered the remaining Python cache concurrency cases. The current-epoch reader proof seeds first. The concurrent size-accounting proof checks committed accounting. The initialized MCP/CLI proof admits each distinct query separately. The earlier 2283 audit missed this case because it accepted the 2275 process-level admission correction without inspecting the second search-all command's internal fan-out. No additional case needs a change.
