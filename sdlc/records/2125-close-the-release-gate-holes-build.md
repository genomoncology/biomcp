## What changed

1. **The release check counts only push runs of ci.yml on main** (`.github/workflows/release.yml`, `version-check`). The green-CI query now carries `--branch main --event push` and pipes through jq in the step's own script, so the count selects `.event == "push" and .headBranch == "main" and .conclusion == "success"`; a failing gh or jq call funnels into the same refusal as a zero count. A commit like 393737eae — failed main run, green ticket-branch run — can no longer release a tag.
2. **The coverage check charges a merge with `git diff --name-only <merge>^1 <merge>`** (`scripts/check-changelog-coverage.py`, `landing_files`). The old `diff-tree -r -m --first-parent` also diffed a merge against its second parent, charging a stale branch's landing with everything main gained since it forked; a landing is now charged with its branch's own files alone, and a linear landing keeps its plain parent diff.
3. **The release workflow runs the release-gate marker set before it builds archives** (`.github/workflows/release.yml`, new `release-gate` job; `Makefile`, new `release-gate-markers` target). `build` and `pypi-build` need the job; the job checks out the tag, fetches the cargo registry, and runs `make release-gate-markers` — the same `-m release_gate` pytest selection `make release-gate` runs, whose centerpiece is the packaged-crate cold compile nothing had run since 2071 moved it behind the marker.
4. **The changelog shape test refuses a repeated bullet and a blank line inside a list** (`tests/test_docs_changelog_refresh.py`), and the duplicate 2079 bullet and the stray blank line are deleted from the 0.9.3 section of `CHANGELOG.md`.
5. **`Cargo.toml` declares `rust-version = "1.89"`**, the floor the ticket's evidence names for the std file locks 2072 introduced. Linux-only, so CI carries it (see Proven and not proven).
6. `.github/workflows/ci.yml` mirrors the release's exact new gh query in the `release-checks` lane, and `tests/test_ci_workflow_contract.py` pins the new fragments; the lane exists to prove the release's flags parse on a real gh on every push, so it must run the command the release actually runs.
7. `tests/test_upstream_planning_analysis_docs.py` pins the Makefile's `.PHONY` line, so the new `release-gate-markers` target moved the pin; the branch's python-lane run caught the stale pin and `823eabe55` moved it (commit "Pin the new release-gate-markers target in the Makefile contract"), and the ticket's Changes line now claims that file. `61252a4ed` (commit "State test-comment constraints without ticket citations") rewrites the nine comments the branch had written with ticket numbers in them, which the lint gate's code-comment scan rejects.
