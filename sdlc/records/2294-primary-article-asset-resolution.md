# Return primary article assets without the secondary ZIP wait

The requested outcome is to return a complete primary PMC asset answer without calling the optional Europe PMC supplementary ZIP. Missing, failed or unusable primary data must still reach the existing fallback and preserve refusal and unavailable labels. This work starts at 63e786985, which adds the ticket to main 3386. The cause is the unconditional ZIP member of the assets resolver's tokio::join!: a complete primary reply still waits for that optional future. PM confirmed ZIP-only scope. Existing XML, HTML and Figshare discovery can add assets and retain their existing budgets.

The implementation changes src/entities/article/assets.rs. It preserves parallel primary/XML/HTML/Figshare observations and consults the ZIP only when the primary lacks usable assets, declared links remain unresolved, or requested bytes are missing. Primary sufficiency does not depend on an unrelated optional XML outage. The bytes entry point passes its requested handle into the existing resolver; the other callers keep their existing interface. An unconsulted ZIP has no fabricated healthy-absent or unavailable attempt. No cache, provider budget, public provider call or clinical judgment is added.

The outside-in regression uses the real CLI, the shared isolated article fixture, and an authored loopback archive with one usable CSV. The optional ZIP accepts a connection without replying. Listing and byte retrieval must preserve the CSV and never request that ZIP, while an optional XML outage remains visible. A second control requires a missing primary filename to consult the ZIP. A third returns a malformed primary archive reply after a measured 200-millisecond delay and requires the valid ZIP fallback. The controlled server handles that delayed primary reply independently from ZIP requests.
